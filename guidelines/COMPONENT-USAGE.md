# 组件定义与使用手册 · v0.12

基础组件处理通用外观与交互；业务组件处理一个有明确数据关系和动作的领域任务；PageAssembly 才负责跨领域组合与状态。业务组件不是整页模板，也不是随意放在一起的卡片。

## 从页面开始选择

- 连续正文、登录、输入银行卡：Page white。
- 分类、商品网格、购物车、结算、订单、评价、地址簿：Page gray，内容卡片 white。
- 原稿是底部选择或确认面板：BottomSheet；独立短确认才用 Dialog。
- 主要提交用 Button；取消、完成、查看、重发、新增入口用 TextButton。
- 列表同层切换用 Tabs；应用主栏目用 TabBar；不要重复添加导航。

## 按钮（Button）

**定义**：有填充或描边的明确操作按钮；执行当前区域的主要或次要任务。

**何时使用**：用户能明确知道点击后会执行什么动作时。

**不要这样用**：只完成上述定义中的任务；路由、接口、金额计算和跨组件状态由组合页管理。

**职责边界**：只负责通用外观与交互，不读取商品、订单或账户接口。

**设计规则 · 按钮尺寸按操作层级使用**：regular 48px 用于提交和结算，medium 40px 用于区域操作，small 36px 用于订单动作和展开/收起，compact 28px 用于记录入口；胶囊背景必须包住文字。 页面只有一个主要操作时，使用内容区通栏按钮，左右与卡片对齐，不能缩成文字宽的小胶囊。

**设计规则 · 结果页原因使用卡片承载**：错误或失败页的多条原因放在同一张白色卡片内，以列表呈现；灰色页面承载白卡。状态图标、标题、原因卡、通栏操作依次排列，不能把多条原因压缩成一段居中文字。

**设计规则 · 中英文正文分别选择字体，价格保持不变**：组件使用 LocaleProvider 设置 en 或 zh-CN。英文正文使用 Poppins，中文正文使用设备已安装的 PingFang SC；不存在时回退 Hiragino Sans GB、Microsoft YaHei、sans-serif。语言切换仅改变正文 --ds-font，不覆盖独立的 --ds-price-font，价格仍为 DdmcSans、Poppins、sans-serif。Page 与弹层保持同一语言。商品名、业务数据及页面文案由调用方提供对应语言；不得根据币种或价格猜测语言。PingFang 字体文件不随公共包分发。

可运行示例：`http://127.0.0.1:5173/?component-preview=Button&variant=default`。所需参数见 COMPONENT-API.md 的同名条目。

## 加购按钮（AddButton）

**定义**：商品图片角落的圆形加购入口；只表达加入购物车这一操作。

**何时使用**：商品被浏览、选择规格、加入购物车或结算前检查时。

**不要这样用**：只完成上述定义中的任务；路由、接口、金额计算和跨组件状态由组合页管理。

**职责边界**：组合领域内的基础组件；接收真实业务数据及事件，不把整张旧页面包装进来。

可运行示例：`http://127.0.0.1:5173/?component-preview=AddButton&variant=default`。所需参数见 COMPONENT-API.md 的同名条目。

## 数量步进器（QuantityStepper）

**定义**：一个商品的数量编辑控件；处理增加、减少、上限和数量为一时禁用减号。

**何时使用**：购物车数量默认下限为 1；商卡加购通过 min={0} 允许减到零，随后恢复加购按钮。

**不要这样用**：购物车删除使用左滑；商卡数量为 1 时减号可点击。不要用垃圾桶替代减号。

**职责边界**：只负责通用外观与交互，不读取商品、订单或账户接口。

**设计规则 · 数量下限按场景区分**：购物车步进器下限为 1，减号保留并置灰，删除使用左滑。商卡加购控件下限为 0，数量为 1 时减号可点击，减到 0 后恢复加购按钮；达到上限时加号禁用。

```tsx
<QuantityStepper value={quantity} onChange={setQuantity} />
```

可运行示例：`http://127.0.0.1:5173/?component-preview=QuantityStepper&variant=default`。所需参数见 COMPONENT-API.md 的同名条目。

## 标签（Tag）

**定义**：不可点击的短状态标签；标记促销、门槛或商品状态。

**何时使用**：绿色说明权益或门槛，灰色说明中性状态；红色 marketing 表示 Save 32% 等促销，红色 warning 表示即将过期等警告。

**不要这样用**：红色不等于危险操作；删除按钮和可选筛选分别用 Button、ChoiceChip。

**职责边界**：只负责通用外观与交互，不读取商品、订单或账户接口。

**设计规则 · 红色标签表示营销或警告**：Tag 的红色用于营销与警告，绿色用于权益和门槛，灰色用于中性状态。可选择标签属于 ChoiceChip，不属于 Tag。

```tsx
<Tag tone="marketing">Save 32%</Tag>
```

可运行示例：`http://127.0.0.1:5173/?component-preview=Tag&variant=default`。所需参数见 COMPONENT-API.md 的同名条目。

## 选择标签（ChoiceChip）

**定义**：可点击的单项选择标签；选中状态由页面传入，适合短选项。

**何时使用**：短选项选择。background="white" 适合灰色页面；background="gray" 适合白色卡片；选中都使用浅绿底与绿色边框。

**不要这样用**：不要让默认示例自带选中状态；标签文字需要完整放进背景内。

**职责边界**：只负责通用外观与交互，不读取商品、订单或账户接口。

**设计规则 · 组件必须与承载背景可区分**：白底上使用灰色组件，或有描边的白色组件；灰底上使用白色或明确的彩色组件。输入框、搜索框和预览容器都要有可见边界，不能融入背景。 优惠券列表、历史券列表、Profile、About 和推荐商品 feeds 流必须使用灰色承载背景与白色卡片；即使原页面误用白底，也按此规则纠正。ProductCollection、VoucherList 自己提供灰色承载层，页面不能把它覆盖回白色。白底上白色组件只有具备明确描边时才可使用。 通用 SVG 包装层修正规则不得命中 VoucherList 或优惠券页面等带明确背景的语义容器；验证时检查浏览器计算后的背景色，不能只检查 CSS 声明。

**设计规则 · 红色标签表示营销或警告**：Tag 的红色用于营销与警告，绿色用于权益和门槛，灰色用于中性状态。可选择标签属于 ChoiceChip，不属于 Tag。

**设计规则 · 选择项提供白底和灰底**：ChoiceChip 需要白色与灰色背景两种外观，并有明确的选中/未选中状态。根据承载背景选择，文字不得超出背景。

**设计规则 · 分类框架独立于页面外壳**：CategoryLayout 提供 text-primary 与 image-primary 两种原稿结构。前者使用文字一级分类和图片二级侧栏；后者使用图片一级分类、文字二级侧栏、三级筛选及排序。框架组合当前 ProductCard，状态栏、底部导航、安全区由 Page 管理；头部背景通过 Page 统一承接。分类栏和商品列表分别滚动，搜索、分类、筛选与排序通过受控接口交给业务层，不复制整页 Screen。

**设计规则 · 表单内容与承载层使用相反明度**：先判断页面背景，再选择组件承载层：灰色页面放白色表单，白色页面放灰色或明确描边的表单；字段与表单再形成层次。灰色内容不能展示在灰色背景上。AddressForm 的 surface 指表单本身颜色；OrderRemarks 使用白色承载层和灰色输入／选项；PromoCodeForm 使用白色承载层和灰色胶囊输入框。 地址与联系人字段名称置于输入框内部，保留可访问的标签，不再逐项占用框外独立标题行。

```tsx
<ChoiceChip background="white" selected={selected} onClick={toggle}>Pack carefully</ChoiceChip>
```

可运行示例：`http://127.0.0.1:5173/?component-preview=ChoiceChip&variant=default`。所需参数见 COMPONENT-API.md 的同名条目。

## 单行输入框（TextField）

**定义**：有名称、占位提示、输入值和校验反馈的单行输入项。

**何时使用**：单行字段必须有真实标签与能说明格式的 placeholder，例如卡号 0000 0000 0000 0000。

**不要这样用**：placeholder 不能替代 label；已有值不能当作 placeholder；错误通过 error 告知。

**职责边界**：只负责通用外观与交互，不读取商品、订单或账户接口。

**设计规则 · 组件必须与承载背景可区分**：白底上使用灰色组件，或有描边的白色组件；灰底上使用白色或明确的彩色组件。输入框、搜索框和预览容器都要有可见边界，不能融入背景。 优惠券列表、历史券列表、Profile、About 和推荐商品 feeds 流必须使用灰色承载背景与白色卡片；即使原页面误用白底，也按此规则纠正。ProductCollection、VoucherList 自己提供灰色承载层，页面不能把它覆盖回白色。白底上白色组件只有具备明确描边时才可使用。 通用 SVG 包装层修正规则不得命中 VoucherList 或优惠券页面等带明确背景的语义容器；验证时检查浏览器计算后的背景色，不能只检查 CSS 声明。

**设计规则 · 输入项提供具体占位信息**：FormField 内的 input 或 textarea 要有 placeholder，描述预期输入。TextArea 的字数上限显示在输入区域内部；焦点样式覆盖整个输入区域。

```tsx
<TextField label="Card number" placeholder="0000 0000 0000 0000" value={number} onChange={e => setNumber(e.target.value)} />
```

**定义**：整行可点击的单选项；同组只能选择一个值。

**何时使用**：用户需要填写、选择、筛选或提交一个值时。

## 评分（Rating）

**不要这样用**：商品用 stars、配送用 sentiment；不能换 Unicode 星字符，也不能用第二排星星展示 Taste 等细分选择。

**职责边界**：只负责通用外观与交互，不读取商品、订单或账户接口。

## 列表行（ListRow）

**定义**：单条设置或信息入口；由标题、说明、前置图标和尾部动作组成。

**何时使用**：设置项、配送时间等单条信息入口；左右各 15px 内距，说明在标题下方，值和箭头在右侧。

**不要这样用**：不要把文字顶到容器边缘；多字段的领域信息应组合成业务组件。

**职责边界**：只负责通用外观与交互，不读取商品、订单或账户接口。

**设计规则 · 按内容关系分配间距**：图标与文字 6–9px，同组标题与说明 6px，说明与控件 12px，卡片间通常 12px，任务分区通常 24px。列表标题距首行 6–12px；不要把多个容器的 padding、margin、gap 重复相加。原稿有明确尺寸时以原稿为准。

**设计规则 · 列表和内容保留左右留白**：页面通常左右 12px；列表行、表单、弹窗正文通常 15–18px。SwipeAction 内容和 ListRow 不能贴边，左右对齐同组内容。

```tsx
<ListRow title="Delivery time" trailing="Today" onClick={chooseTime} />
```

可运行示例：`http://127.0.0.1:5173/?component-preview=ListRow&variant=default`。所需参数见 COMPONENT-API.md 的同名条目。

## 底部抽屉（BottomSheet）

**定义**：从页面底部出现的任务面板；背景保留上下文，内容过长时内部滚动。

**何时使用**：从当前页面选择支付方式、地址、配送时段、商品规格，或确认提交评价。

**不要这样用**：不能擅自换成居中 Dialog；最大高度 88%，超出只滚内容，操作区保持可见。

**职责边界**：只负责通用外观与交互，不读取商品、订单或账户接口。

**设计规则 · 列表和内容保留左右留白**：页面通常左右 12px；列表行、表单、弹窗正文通常 15–18px。SwipeAction 内容和 ListRow 不能贴边，左右对齐同组内容。

**设计规则 · 文字角色决定字阶**：导航和底部弹窗标题使用 18/23px，正文 14/19px，辅助文案 12/18px；文字不因模板复用随意放大。状态标签使用常规字重，价格保留币种、整数和小数的明确层级。

**设计规则 · 地址选择打开抽屉**：购物车头部地址入口打开地址 BottomSheet，选择后更新地址并关闭面板。重复地址标签的确认保持底部弹窗，展示原地址摘要和纵排操作，不改为居中对话框。

## 状态文字（StatusLabel）

**设计规则 · 先分析组成，再复用已有组件**：按验收原稿拆解页面的容器、列表、提示和操作。已有组件必须通过正确参数组合；确无能力时才补充组件。取消原因必须是 BottomSheet＋RadioRow 列表＋Switch 提示条＋吸底 Confirm，不改为独立全屏表单，不增加原稿没有的输入区。

**设计规则 · 表单内容与承载层使用相反明度**：先判断页面背景，再选择组件承载层：灰色页面放白色表单，白色页面放灰色或明确描边的表单；字段与表单再形成层次。灰色内容不能展示在灰色背景上。AddressForm 的 surface 指表单本身颜色；OrderRemarks 使用白色承载层和灰色输入／选项；PromoCodeForm 使用白色承载层和灰色胶囊输入框。 地址与联系人字段名称置于输入框内部，保留可访问的标签，不再逐项占用框外独立标题行。
